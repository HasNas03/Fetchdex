Fetchdex: Semantic Search and Grounded RAG

Fetchdex provides two terminal commands backed by one local Chroma document index.

client-provided .txt/.md file or folder
        ↓
index command synchronizes the documents
        ↓
Chroma
        ├── search → matching text and files
        └── ask    → Qwen answer and sources

1. Files and Responsibilities

FileResponsibility
semantic.pyLoad, chunk, embed, index, and retrieve documents.
rag.pyTurn retrieved evidence into a grounded Qwen answer.
cli.pyRun indexing, search, or RAG commands and display results.
evaluation.pyEvaluate retrieval and RAG against the golden dataset.

2. Indexing

python fetchdex index "/path/to/notes"
        ↓
cli.main()
        ↓
index_documents()
        ↓
load → chunk → embed → update Chroma

Folder paths are scanned recursively for .txt and .md files. Re-index after changing those files. The new index replaces the previous document set; search and ask reuse it without needing the path.

3. Semantic Search

python fetchdex index "/path/to/notes"
python fetchdex search "database migration" --chunks 3
run_search()
    ↓
embed query → retrieve closest Chroma chunks
    ↓
print text and source filenames

This workflow does not call Qwen.

4. Grounded RAG

python fetchdex ask "Which AWS service can migrate databases?" --chunks 3
run_ask()
    ↓
rag_search() → semantic retrieval
    ↓
document evidence → Ollama / Qwen
    ↓
answer and source filenames
Answer:
AWS DMS can migrate databases.

Sources:
- test_doc2.txt

The Sources section shows which file supplied the retrieved evidence.

5. Evaluation

python -m source.evaluation retrieval
python -m source.evaluation rag

6. Setup and Tests

cd ~/Desktop/Fetchdex
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
ollama pull qwen3:1.7b
ollama serve
python -m unittest discover -s tests -v
